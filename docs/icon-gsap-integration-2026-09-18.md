# 5.2 · 图标规范与 GSAP 接入决定 · 2026-09-18

## 图标

用户对同一 Agent 工作台的 Hugeicons / Iconoir 版本对照后选择 Hugeicons。新建、无既有品牌约束的产品优先使用 Hugeicons Free Stroke Rounded；已有或用户指定图标体系保持不变。Iconoir 保留为有明确理由时的备选，不强制每次重新投票。

规范同时覆盖真实界面选型、不同层级的视觉重量、同家族语义与状态、尺寸与光学校正、无障碍、包名/版本/授权，以及插画和界面图标的边界。入口位于主控 icon-system.md，并贯穿设计合同、组件几何与 QA。

## GSAP：采用内置轻量执行规范 + 官方主题参考

| 方案 | 收益 | 成本与边界 | 结论 |
| --- | --- | --- | --- |
| 全局安装官方 8 Skills，由主控调用 | 独立 GSAP 开发可直接发现 | 泛触发与已有 HyperFrames/交互规则重叠；仍需审核上游规则 | 本次不装；专门 GSAP 工程可按需另行配置 |
| 整套复制为新子 Skill / 拆成八成员 | 随包可用 | 扩大六成员安装契约、维护副本与版本漂移；增加上下文入口 | 不采用 |
| 现有交互 Skill 内置有边界的执行规范，按主题链接官方资料 | 保持六成员；主控意图和验收统一；基础约束离线可读 | 高级 API 仍需对应版本官方文档 | 采用 |

调用链：主控确定动效任务与工具 → ui-interaction-reference / gsap-execution.md → 仅当前主题的官方资料 → 消费项目实现与真实交互验收。

CSS、Motion、原生转场仍按适用场景使用；HyperFrames 的 GSAP Skill 保持视频场景边界。设计栈安装不会安装 GSAP npm 包、官方八 Skills 或图标运行时。

上游检查固定在 greensock/gsap-skills 的 aed9cfd3277740755f6bfc1155c7aa645403b760。已对照官方 API 修正三点：refreshPriority 越高越早；Flip 的 scale 非默认 true；contextSafe 不负责取消全部异步回调或移除监听器。执行规范保留直接来源链接。
