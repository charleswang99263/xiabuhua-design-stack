# Host and runtime boundary

All six skill directories are siblings. A host supporting SKILL.md may discover them natively; otherwise read the selected entry and its relative references. No workflow requires Codex APIs, subagents, a connected design tool or image generation merely to reason about design. Use available tools and state actual artifact fidelity.

Local museum and labs use ordinary HTML/CSS/JS. Their entry files and adjacent primitives/vendor assets must travel together. Original data/tactile modules are dependency-light; the graphics lab has explicitly versioned libraries and accompanying licenses. Do not copy an entire lab into every product; reuse only the selected source and dependencies. The 24-image atlas is optional visual evidence, not startup context or a runtime dependency of ordinary work.

Python helper scripts require Python3; PPTX inventory additionally needs python-pptx. Shell helpers require Bash. Automated deck PDF uses Node, Playwright and a browser; browser Print to PDF is an alternative requiring page-size verification. Diagram SVG is portable; PNG rendering requires a browser, CairoSVG or rsvg-convert. Do not download dependencies or authenticate services as an unannounced side effect of reading a skill.

External design, data and bitmap-generation tools are optional host capabilities, not bundled accounts or software. Missing capabilities require a truthful boundary; do not claim editable design access or real 3D rendering from screenshots. Platform-specific metadata can be ignored by other hosts. Preserve third-party license notices when redistributing dependency files.

Keep one active installed copy of the suite per host discovery scope. Author source outside discovery roots; migrate exact suite members together, move old copies outside active discovery, and verify file hashes plus host visibility. Never remove unrelated skills by a name prefix. Backups are not active skills. Re-read host discovery state after refresh/new session before claiming duplicate entries are gone.
