# Visual executor handoff

Read when a task crosses a tool/skill boundary. Send the style agreement and selected specimen with the executor's bounded job. Do not send only an aesthetic adjective. An executor can develop details within the direction and report real incompatibilities; it cannot silently choose a replacement identity.

Include the [implementation map](style-implementation.md): defining relationships, DOM/layout, typography roles, graphic assets, material and state strategy, plus ordinary-surface evidence. A token list or a profile name alone is incomplete. Main-skill narrative composition stays authoritative; executors implement its supplied blueprint.

When a specimen recipe is selected, pass its resolved element list (including exclusions and real asset paths/status), color-role tokens, typography roles, layout regions/ratios, material/light model and allowed adaptations. Executors cannot replace a complex subject with generic icons, flatten a material-led direction to ordinary cards, substitute their default fonts/palette, or change the focal hierarchy for convenience. Return a per-dimension match/deviation/unverified record against the selected specimen; escalate missing assets or incompatible behavior to the main workflow instead of silently weakening the direction.

| Executor | Pass | Preserve | Check on return |
| --- | --- | --- | --- |
| html-deck-runtime | resolved slide blueprint, layout/assets, content, interaction and runtime specification; parent retains selection authority | supplied specification, fixed stage, navigation and truthful source content | main skill compares cover/body to its selected specimen; executor checks only implementation, not aesthetics or selection |
| component museum / UI reference | component job, state/data, direction, allowed intensity, runtime | input→state→meaning, project tokens and asset language | real feedback, matching visual treatment, reduced-motion/input alternatives |
| Data Analytics | validated sources/metric definitions, report vs dashboard task, direction/specimen, explicit HTML or other selected delivery | quantities, scales, comparison basis, caveats and provenance | no automatic KPI-card wall; styling and layout serve the chosen reading/operation task |
| diagrams | topology/labels/semantics plus type/line/shape/palette agreement | accurate relationships and source meaning | no fallback palette/shape replacing the project direction |
| raster assets | exact subject/role/dimensions/crop plus material, palette, texture and reference | actual requested medium, source truth and user-approved art direction | specimen-compatible assets, not generic stock-like filler or copied third-party identity |
| Figma/Sketch/MasterGo | selected target, reusable tokens/components, platform context and editable-source scope | native component/variable truth and platform constraints | direction match on real rendered screens, not just token names |
| image-to-code / other visual-target workflow | exact selected specimen/frame/image and agreement, with agreed adaptations | the chosen target and required runtime infrastructure | no repeated ideation merely because the executor has its own default picker |

Use the currently available tool and its actual instructions. Adapter guidance does not override a user's instruction, capability limitation, safety rule or license. Do not modify plugin caches to resolve a conflict. If a required output cannot be made with the selected mechanism, describe the evidenced incompatibility and smallest viable change before expanding work.

Use the existing DESIGN.md or design-delta record as the one authority. Only candidate work can proceed when confirmation is pending. When finished, return source/preview path, preserved invariants, permitted adaptations, actual checks and remaining deviations. A “looks consistent” conclusion without specimen comparison is insufficient.
